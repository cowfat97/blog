    vLLM 安装与运行

    在 Windows 11 + WSL2 + NVIDIA GPU 环境中安装 vLLM，并以 OpenAI 兼容 API 方式运行 Qwen/Qwen3-4B。

    本文记录当前设备的实际环境和可复现的操作步骤。具体的改造对比、异常注入和性能指标见 vLLM 改造实验。

    1 最终架构

    vLLM 不原生支持 Windows CUDA 运行方式，因此当前项目分为两个环境：

    Windows
  C:\Workspace\code\Qwen\.venv
  运行 FastAPI、ReAct、Memory 和 vLLM HTTP 客户端
                         |
                         | http://127.0.0.1:8001/v1
                         v
WSL2 / Ubuntu 24.04
  ~/vllm-env
  运行 vLLM、PyTorch CUDA 和 Qwen3-4B

    端口分工：

    端口 服务
    8000 Windows 中的项目 FastAPI POST /chat
    8001 WSL 中的 vLLM OpenAI 兼容 API

    两个 Python 环境完全独立。Windows .venv 中的 PyTorch 是否支持 CUDA，不影响 WSL 中的 vLLM 使用 GPU。

    2 当前已验证环境

    2026-09-12 实际读取结果：

    项目 实际值
    Windows Windows 11 专业版 64 位
    WSL 发行版 Ubuntu-24.04
    WSL 版本 2
    GPU NVIDIA GeForce RTX 5060 Ti 16GB
    Windows NVIDIA 驱动 616.92
    WSL NVIDIA-SMI 615.71.08
    CUDA UMD 13.4
    vLLM 虚拟环境 /home/haoxi/vllm-env
    Python 3.12.14
    vLLM 0.28.0
    PyTorch 2.13.0+cu132
    PyTorch CUDA Runtime 13.2
    torch.cuda.is_available() True
    PyTorch 识别的 GPU NVIDIA GeForce RTX 5060 Ti

    注意：当前设备还存在一个早期创建的空环境：

    ~/envs/llm-vllm

    该环境只有 pip、setuptools 和 wheel，没有安装 vLLM 和 PyTorch。后续统一使用：

    ~/vllm-env

    如果终端前缀显示 (llm-vllm)，不代表已经进入正确环境；必须通过 which python 和 python -m pip show vllm 确认。

    3 安装 WSL2 和 Ubuntu

    在管理员 PowerShell 中查看可安装发行版：

    wsl --list --online

    安装 Ubuntu 24.04：

    wsl --install -d Ubuntu-24.04

    查看已安装发行版：

    wsl --list --verbose

    当前设备的发行版全名是 Ubuntu-24.04，因此启动命令是：

    wsl -d Ubuntu-24.04

    不能使用：

    wsl -d Ubuntu

    否则会出现：

    WSL_E_DISTRO_NOT_FOUND

    设置默认发行版：

    wsl --set-default Ubuntu-24.04

    以后可直接输入：

    wsl

    4 验证 GPU 透传

    进入 Ubuntu 后执行：

    nvidia-smi

    当前设备已经正常显示：

    NVIDIA GeForce RTX 5060 Ti
16311 MiB
CUDA UMD Version: 13.4

    WSL 中不要再安装 Windows NVIDIA 驱动。WSL GPU 依赖 Windows 主机驱动的 GPU 透传。

    5 准备 Ubuntu 基础环境

    sudo apt update
sudo apt upgrade -y
sudo apt install -y python3-venv python3-pip git curl

    查看系统 Python：

    python3 --version

    系统 Python 只用于准备工具，vLLM 应该运行在独立虚拟环境中。

    6 使用 uv 创建 vLLM 环境

    检查 uv：

    uv --version

    如果没有安装 uv：

    curl -LsSf https://astral.sh/uv/install.sh | sh
source ~/.bashrc
uv --version

    创建独立环境：

    uv venv ~/vllm-env --python 3.12 --seed

    激活：

    source ~/vllm-env/bin/activate

    确认当前解释器：

    which python
python --version

    预期路径：

    /home/haoxi/vllm-env/bin/python

    虚拟环境前缀只是提示文本，不能代替 which python 的实际检查。

    7 安装 vLLM

    在 ~/vllm-env 已激活的情况下：

    uv pip install vllm --torch-backend=auto

    如果不使用 uv，也可以使用：

    python -m pip install --upgrade pip setuptools wheel
python -m pip install vllm

    python -m pip 的意义是强制使用当前 Python 解释器对应的 pip，避免将依赖误装到系统 Python 或另一个虚拟环境。

    三个基础安装工具：

    工具 作用
    pip 下载和安装 Python 包
    setuptools 兼容仍使用传统构建流程的包
    wheel 支持优先安装预编译 .whl 包

    8 验证 vLLM 和 CUDA

    每次新开 Ubuntu 终端后先激活正确环境：

    source ~/vllm-env/bin/activate

    查看版本：

    python --version
vllm --version
python -m pip show vllm torch

    检查 PyTorch CUDA：

    python -c "import vllm, torch; print('vLLM:', vllm.__version__); print('PyTorch:', torch.__version__); print('CUDA:', torch.version.cuda); print('GPU可用:', torch.cuda.is_available()); print('GPU:', torch.cuda.get_device_name(0))"

    当前实测输出：

    vLLM: 0.28.0
PyTorch: 2.13.0+cu132
CUDA: 13.2
GPU可用: True
GPU: NVIDIA GeForce RTX 5060 Ti

    驱动显示 CUDA 13.4，PyTorch 显示 CUDA 13.2，这不是冲突。前者是驱动可支持的 CUDA 能力，后者是 PyTorch wheel 自带的 CUDA Runtime。只要 torch.cuda.is_available() 为 True 并正确识别 GPU，就可以继续。

    9 启动 Qwen3-4B

    每次启动前确认环境：

    source ~/vllm-env/bin/activate
which vllm
vllm --version

    启动服务：

    vllm serve Qwen/Qwen3-4B \
  --host 0.0.0.0 \
  --port 8001 \
  --dtype auto \
  --max-model-len 8192 \
  --gpu-memory-utilization 0.80

    参数说明：

    参数 作用
    Qwen/Qwen3-4B Hugging Face 模型名
    --host 0.0.0.0 允许 Windows 主机访问 WSL 服务
    --port 8001 避开业务 FastAPI 的 8000 端口
    --dtype auto 根据模型与硬件自动选择精度
    --max-model-len 8192 首轮实验把最大上下文限制为 8192
    --gpu-memory-utilization 0.80 初始允许 vLLM 使用 80% GPU 显存

    首次启动会下载模型。下载和加载期间不要重复启动多个 vLLM 进程。

    该 Ubuntu 窗口必须保持运行。终端返回 shell 提示符或按 Ctrl+C 后，服务就会停止。

    10 测试 vLLM 接口

    在 WSL 中查看模型

    另开一个 Ubuntu 终端：

    curl http://127.0.0.1:8001/v1/models

    应该返回包含 Qwen/Qwen3-4B 的模型列表。

    在 WSL 中发送对话

    curl http://127.0.0.1:8001/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen/Qwen3-4B",
    "messages": [
      {"role": "user", "content": "请用一句话介绍大语言模型。"}
    ],
    "max_tokens": 128,
    "temperature": 0.7,
    "chat_template_kwargs": {
      "enable_thinking": false
    }
  }'

    在 Windows PowerShell 中访问 WSL

    Invoke-RestMethod http://127.0.0.1:8001/v1/models

    对话测试：

    $body = @{
    model = "Qwen/Qwen3-4B"
    messages = @(
        @{ role = "user"; content = "请用一句话介绍大语言模型。" }
    )
    max_tokens = 128
    temperature = 0.7
    chat_template_kwargs = @{
        enable_thinking = $false
    }
} | ConvertTo-Json -Depth 5

Invoke-RestMethod \
    -Uri "http://127.0.0.1:8001/v1/chat/completions" \
    -Method Post \
    -ContentType "application/json; charset=utf-8" \
    -Body ([Text.Encoding]::UTF8.GetBytes($body))

    11 Python 客户端

    Windows 业务虚拟环境安装 OpenAI 客户端：

    cd C:\Workspace\code\Qwen
.\.venv\Scripts\python.exe -m pip install openai

    最小调用：

    from openai import OpenAI

client = OpenAI(
    base_url="http://127.0.0.1:8001/v1",
    api_key="EMPTY",
    timeout=300,
)

response = client.chat.completions.create(
    model="Qwen/Qwen3-4B",
    messages=[
        {"role": "user", "content": "请用一句话介绍大语言模型。"}
    ],
    max_tokens=128,
    temperature=0.7,
    extra_body={
        "chat_template_kwargs": {
            "enable_thinking": False,
        }
    },
)

print(response.choices[0].message.content)

    api_key="EMPTY" 只是 OpenAI SDK 要求该参数不能为空。本地 vLLM 未配置 --api-key 时，它不代表真实凭据。

    12 JSON Schema 结构化输出

    当前 ReAct 协议：

    from typing import Literal

from pydantic import BaseModel


class ActionOutput(BaseModel):
    thought: str
    action: Literal["answer", "memory_search"]
    argument: str

    请求 vLLM 时传入 Schema：

    response = client.chat.completions.create(
    model="Qwen/Qwen3-4B",
    messages=turns,
    max_tokens=512,
    temperature=0,
    response_format={
        "type": "json_schema",
        "json_schema": {
            "name": "action_output",
            "schema": ActionOutput.model_json_schema(),
        },
    },
    extra_body={
        "chat_template_kwargs": {
            "enable_thinking": False,
        }
    },
)

model_output = response.choices[0].message.content
output = ActionOutput.model_validate_json(model_output)

    vLLM JSON Schema 只替代 Outlines 的 Token 级语法约束，不替代：

    • ReAct 业务状态机
    • Pydantic 二次校验
    • 工具调用次数限制
    • 有限重试
    • 超时、断连和空响应处理
    • 最终降级与熔断

    完整链路：

    ReAct 状态机
  → vLLM JSON Schema 约束解码
  → Pydantic 二次校验
  → 有限分类重试
  → 确定性降级与熔断

    13 VS Code 使用 WSL 环境

    vLLM 服务不需要把 WSL Python 设为 Windows 项目的默认解释器。

    Windows 业务代码继续选择：

    C:\Workspace\code\Qwen\.venv\Scripts\python.exe

    如果要在 VS Code 中查看或调试 WSL 内部环境，应用 VS Code 的 WSL 远程窗口打开 Linux 目录，然后选择：

    /home/haoxi/vllm-env/bin/python

    不要在 Windows VS Code 解释器列表中把 /home/haoxi/... 当作 Windows 路径使用。

    14 启停顺序

    每次开发：

    1. 进入 Ubuntu-24.04
2. source ~/vllm-env/bin/activate
3. 启动 vllm serve，监听 8001
4. 验证 /v1/models
5. 启动 Windows FastAPI，监听 8000
6. 调用 POST /chat

    停止：

    1. 在 vLLM 终端按 Ctrl+C
2. 在 FastAPI 终端按 Ctrl+C
3. 如需完全停止 WSL，在 PowerShell 执行 wsl --shutdown

    wsl --shutdown 会停止所有 WSL 发行版和其中的进程，不要在模型服务仍需使用时执行。

    15 常见问题

    WSL_E_DISTRO_NOT_FOUND

    原因：使用了 wsl -d Ubuntu，但实际发行版名为 Ubuntu-24.04。

    处理：

    wsl --list --verbose
wsl -d Ubuntu-24.04

    激活了环境，但找不到 vLLM

    原因：进入了早期空环境 ~/envs/llm-vllm，而不是实际环境 ~/vllm-env。

    处理：

    deactivate 2>/dev/null || true
source ~/vllm-env/bin/activate
which python
which vllm
python -m pip show vllm torch

    torch.cuda.is_available() 为 False

    依次检查：

    nvidia-smi
which python
python -m pip show torch
python -c "import torch; print(torch.__version__); print(torch.version.cuda); print(torch.cuda.is_available())"

    如果 PyTorch 版本带 +cpu，说明当前环境安装了 CPU wheel。不要把 Windows .venv 的检查结果与 WSL ~/vllm-env 混为一谈。

    Windows 无法访问 8001

    先在 WSL 内测试：

    curl http://127.0.0.1:8001/v1/models

    再确认 vLLM 使用：

    --host 0.0.0.0 --port 8001

    然后在 Windows PowerShell 测试：

    Invoke-RestMethod http://127.0.0.1:8001/v1/models

    CUDA Out of Memory

    首先降低：

    --gpu-memory-utilization 0.70
--max-model-len 4096

    同时检查是否有其他模型或 GPU 程序占用显存：

    nvidia-smi

    不要一开始就把 --gpu-memory-utilization 调到 0.95；先保证稳定启动，再根据实测逐步增加。

    首次生成比后续请求慢

    可能包含：

    • 模型冷启动
    • CUDA Kernel 初始化
    • CUDA Graph 准备
    • JSON Schema 首次编译
    • Hugging Face 模型或 tokenizer 首次读取

    性能实验应区分冷启动、预热请求和稳态请求。

    16 模型升级

    当前默认目标：

    Qwen/Qwen3-4B

    16GB 显存的建议顺序：

    模型 用途
    Qwen/Qwen3-1.7B 最小链路验证
    Qwen/Qwen3-4B 默认稳定档
    Qwen/Qwen3-8B-AWQ 4-bit 量化能力档

    8B BF16 权重的理论显存占用已接近 16GB，还需要预留 KV Cache、CUDA Context 和 vLLM 本身开销，因此 16GB 单卡优先实验 Qwen/Qwen3-8B-AWQ，不直接把 8B BF16 作为默认配置。

    18 与 Git 分支的关系

    main：保存 Transformers + Outlines 裸跑基线
vllm：只实现 vLLM HTTP 推理路径

    vllm 分支不保留 Transformers/Outlines 双后端开关，也不在 vLLM 请求失败时自动加载 Windows 本地模型。

    vLLM 不可用时，单次请求由业务层的超时、有限重试、降级和熔断处理；需要恢复旧实现时，通过 Git 切回 main 分支。
