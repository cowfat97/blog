    Qwen3 参数汇总

    01_quick_start.py 涉及的参数按调用位置分三大类型：加载模型（from_pretrained）、拼接对话格式（apply_chat_template）、生成和其他（tokenizer / generate）。本文汇总三类参数的作用与关键概念；采样参数在第 3 节展开详解。

    1 加载模型 from_pretrained

    参数 值 作用
    model_name "Qwen/Qwen3-1.7B" 模型标识「机构/模型」，决定从哪个仓库下载哪个模型；换 "Qwen/Qwen3-8B" 就换模型
    torch_dtype "auto" 加载时权重在内存里的数值精度（bf16 / fp32）；不影响下载内容
    device_map "auto" 加载完成后权重放哪块设备（GPU / MPS / CPU）；与下载无关

    两个概念要分清：

    下载 vs 加载：model_name 决定下载哪个仓库（固定一份权重，约 3.4GB，bfloat16 存盘，不存在「多个版本挑一个」）；torch_dtype / device_map 在下载之后的加载阶段起作用。要换量化版本 = 换仓库名 + 换加载工具（GGUF 走 llama.cpp / Ollama；AWQ / GPTQ 走 transformers + 专用库）。

    torch_dtype（精度）vs 量化：

    torch_dtype（精度） 量化
    本质 数值格式：bf16 / fp32 / fp16 把权重压成 8bit / 4bit
    发生时机 加载时在内存里转换 提前重新压缩，生成新权重文件
    文件 不变，同一份 变，GGUF / AWQ / GPTQ 是新仓库新文件
    内存 bf16 比 fp32 省一半 4bit 比 bf16 再省约一半
    精度损失 几乎无 有损（8bit 基本无损，4bit 轻微）

    两者都是省内存手段：一个在加载层转换格式，一个在文件层重新压缩。工程术语里 bf16 是「精度」，int8 / int4 才叫「量化」。

    2 拼接对话格式 apply_chat_template

    参数 值 作用
    messages 消息列表 [{"role": "user", "content": "..."}]，role 有 system / user / assistant / tool
    tokenize False 只拼文本不转数字；True 直接返回 token id
    add_generation_prompt True 末尾追加「助手开口」标记，告诉模型该它说话了
    enable_thinking False 思考模式开关；True 先输出 <think> 思考过程再给答案

    tokenize：tokenizer 做「文字 ↔ 数字」双向转换。False 时只拼成人类可读文本，方便看格式；下一步 tokenizer([text], return_tensors="pt") 才转数字。注意：tokenizer 出的是 token id（整数编号），不是向量——id 进到模型内部才由 embedding 层查表变成向量。

    add_generation_prompt：拼完消息后末尾追加 <|im_start|>assistant，等于给模型起个头「助手：____」，模型顺着填空。不写的话模型可能输出空、或重复用户的话。

    模板实际拼出来的文本（实际运行结果）：

    <|im_start|>user
请用中文介绍一下大语言模型。<|im_end|>
<|im_start|>assistant

    <|im_start|> / <|im_end|> 是消息开始/结束标记，模型靠它们区分「谁在说话」；末尾多出的 <|im_start|>assistant 就是 add_generation_prompt 加出的「半截话头」。

    类比：给模型一张印好「用户问题」和「助手：」的答题卡，模型从「助手：」后面开始写答案——它只会续写，没有话头就没法开始。

    模型生成 = 续写：把拼好的完整文本一次喂进去，模型从最后一个 token 开始一个词一个词往后写，写出的就是助手该说的话。generate() 返回的 generated_ids 是「输入 + 新生成」拼接的完整序列，用切片截掉输入部分就是续写内容。多轮对话「记得」上文靠的也是把历史拼进输入，不是模型内部有记忆。

    apply_chat_template 控制的是输入结构，不是响应。控制响应结构的是：enable_thinking（是否带思考段）、max_new_tokens（长度）、输出格式约束（专题文章）。

    3 生成和其他

    参数 值 作用
    return_tensors "pt" 返回 PyTorch 张量（模型只认这个格式）；不写返回 Python 列表，generate 不认
    max_new_tokens 512 最多生成 512 个新 token（约 700 汉字）
    temperature / top_p / top_k 未写 采样参数，控制生成随机性（详解见 3.1）

    return_tensors：tokenizer 默认返回 Python 列表（一串数字）；模型计算要的是 torch.Tensor——带 shape（[1, 33]）、device（cpu / mps）、dtype（int64）三个属性。"pt" 让 tokenizer 一步到位返回张量，省掉手动转换。

    为什么全是矩阵不是文字：模型全程只算数字——文字 → token id → embedding 向量 → Transformer 矩阵计算 → logits 矩阵（每个位置给词表全部 151k+ 个候选打分）→ 挑最高分 id → 查词表换回文字。你看到的「输出文字」是 generate + decode 封装后的结果。

    另外 151668 不是参数，是 </think> 的 token id。enable_thinking=True 时输出分两段：<think>...</think> 思考过程 + 正文。解析用 151668 切：从后往前找（思考内容里可能出现过类似标记，取最后一个最可靠），之前是思考、之后是正文；try/except 兜底没找到的情况（模型没输出思考，全部按正文处理）。

    3.1 采样参数：模型怎么挑词

    生成一个 token 的完整过程：模型算出当前位置每个候选词的分数（logits）→ softmax 转成概率分布（总和 1）→ 按策略挑一个 → 输出这个词 → 循环到下一个位置。采样参数控制的只有第三步「怎么挑」。

    三种挑法

    1. 贪心（greedy）：永远挑概率最高的词。确定、快，但死板，容易绕圈重复。do_sample=False 就是它
    2. 采样（sampling）：按概率随机抽——概率 0.7 的词有 70% 机会被选中。输出多样、更像人。do_sample=True 才是它
    3. 束搜索（beam search）：同时保留 k 条候选序列，每条都往后写，最后选总分最高的。翻译类任务常用；transformers 里 num_beams>1 开启。聊天场景少用

    两个容易混的点：

    • 「给概率」≠「按概率抽」：softmax 的概率分布只是中间产物。概率 0.7 的词，贪心 100% 选它（另外 30% 看都不看），采样只有 70% 选它。模型默认贪心（do_sample=False），拿到分布只取最高分一个，其余候选的概率等于白算
    • 贪心 vs 束搜索：贪心是每一步挑当前最高分（局部最优），第 1 步锁死后不能反悔；束搜索是整条序列比总分（全局搜索），每步留 k 条路走到最后再比。数字例子：第 1 步 A=0.5、B=0.3，A 后最好只能接 0.1（整条 0.05），B 后最好能接 0.8（整条 0.24）——贪心锁死 A 只得 0.05，束搜索留着 B 最后 0.24 赢。贪心 = 束搜索 k=1 的特例；两者都是确定性搜索（同输入同输出），随机性是采样独有的

    每一步的概率是条件概率：基于前面已写的内容算。写了「我」之后，第 2 步的分布是在「我」的前提下算的——「我」后面再接「我」概率极低，通常接动词（我去 / 我吃 / 我想）。

    概率是怎么用的

    • 加权抽签：概率当权重——0.7 的词抽中概率就是 70%，抽 100 次约 70 次是它。概率控制「倾向」和长期比例，不是「必然」。随机性买来的是多样和自然，像人说话
    • 区间法实现：每个词分一段区间，区间长度 = 概率（我 [0, 0.7)、你 [0.7, 0.9)、它 [0.9, 1)），生成一个 [0, 1) 随机数，落在谁的区间选谁。一次线性扫描，15 万词表微秒级，词表不会变大。PyTorch 的 torch.multinomial 封装的就是这个
    • 圈池子（top_k / top_p 干的事）：只留前几名再抽，不是采样本身的定义。纯采样是所有候选一起按概率抽——0.05 的低分词也有机会被抽中

    三个参数

    • temperature（温度）：先把 logits 除以 T 再 softmax。T 越小分布越尖（趋近贪心），越大越平（趋近均匀随机）。公式：P(i) = exp(logit_i / T) / Σ exp(logit_j / T)。0 = 贪心；0.2~0.4 保守稳定；0.6~0.8 自然；>1 发散
    • top_k：只留分数最高的 k 个候选，其余概率清零。20 = 只看前 20 名
    • top_p（核采样）：从高分往低分累加概率，累到总和 p 就停，池子外全部清零。候选数动态

    执行顺序：temperature 缩放 → top_k / top_p 过滤 → 重新归一化 → 抽样。

    配置

    model.generate(
    **inputs,
    do_sample=True,    # 开关：不写这个，下面三个参数全失效（默认贪心）
    temperature=0.7,
    top_p=0.8,
    top_k=20,
)

    官方推荐：思考模式 0.6 / 0.95 / 20；非思考 0.7 / 0.8 / 20。

    怎么选值

    • 要稳定：温度 0.2~0.4（代码生成、事实问答）
    • 日常对话：0.6~0.8 + top_p 0.9 左右
    • 创意写作：0.9~1.2
    • 调参顺序：先固定 top_p=0.9 / top_k=40，只调温度，感知最直观

    验证实验：同一 prompt，temperature 0.2 / 0.7 / 1.2 各跑两遍，观察重复与发散，动手步骤见 采样温度实验。
