    记忆压缩实验

    实验目的

    在终端会话中加入 /compact 命令，由用户主动触发历史消息压缩，观察压缩能否减少上下文长度，同时保留后续回答需要的关键信息。

    本实验重点回答：

    • /compact 应该由哪一层识别和执行
    • 规则裁剪与 LLM 摘要压缩有什么区别
    • 压缩后模型能否继续召回旧事实
    • 多次压缩是否会造成信息持续丢失
    • 压缩能减少多少字符或 Token，又增加多少处理时间

    本轮只研究手动命令，不同时加入自动压缩和模型自主调用，避免混淆触发机制与压缩效果。

    概念边界

    机制 谁决定执行 是否发送给主对话模型
    /compact 命令 用户 命令本身不发送
    memory_compact Tool 模型 模型主动产生 Tool Call
    自动压缩 程序阈值 达到阈值后自动执行

    本实验使用第一种：

    用户输入 /compact
  → 命令解析器拦截
  → 不把 /compact 写入普通会话
  → 读取可压缩的历史消息
  → 生成历史摘要
  → 重组 messages
  → 输出压缩统计
  → 等待下一条用户消息

    /compact 是命令系统的入口；真正生成摘要的函数才是记忆压缩能力。

    压缩后的消息结构

    system：原始系统提示
system：[历史摘要] 用户叫郝鑫磊；正在学习 Qwen；已经讨论……
user：最近保留的用户消息
assistant：最近保留的助手回复

    必须满足：

    1. 系统提示始终位于第一条，不能参与摘要或被覆盖。
    2. 历史摘要有明确标记，能够与普通用户消息区分。
    3. 最近若干轮保留原文，维持当前讨论的局部连贯性。
    4. /compact 本身不作为用户知识写入记忆。

    实验假设

    1. 全量保留历史的信息最完整，但上下文会持续增长。
    2. 直接删除旧消息最节省空间，但旧事实召回能力最差。
    3. LLM 摘要能在上下文长度与信息保真度之间取得平衡。
    4. 对摘要反复进行二次总结，会逐渐丢失姓名、数字和条件等细节。
    5. 保留最近若干轮原文，可以降低压缩后对话突然断裂的问题。

    控制变量

    各组保持以下条件一致：

    • 使用同一个模型和模型版本
    • 使用相同的生成参数
    • 使用完全相同的历史对话
    • 使用相同的后续测试问题
    • 使用相同的最近消息保留数量
    • 每个用例重复运行相同次数

    主动改变的变量只有历史消息处理方式。

    实验分组

    A：全量保留

    system + 全部历史原文 + 当前问题
    • 不执行压缩
    • 作为信息保真度上限
    • 记录上下文持续增长的速度

    B：规则裁剪

    system + 最近 N 轮原文 + 当前问题
    • 直接删除较早消息
    • 不调用 LLM
    • 观察旧事实丢失情况

    C：LLM 摘要压缩

    system + 历史摘要 + 最近 N 轮原文 + 当前问题
    • 用户输入 /compact 后调用模型总结旧消息
    • 用摘要替换已经被总结的历史原文
    • 观察压缩率、信息保真度和压缩耗时

    D：重复摘要压缩

    第一次 /compact
  → 历史摘要 1
继续对话
  → 第二次 /compact
  → 历史摘要 2
    • 验证多次压缩是否产生递归信息衰减
    • 比较第一次与第二次摘要保留的事实

    /compact 命令契约

    输入

    /compact

    第一版不增加参数，保留数量由程序中的固定配置决定，避免把命令参数设计混进压缩实验。

    成功输出

    压缩完成：
消息数：20 → 7
字符数：5200 → 1800
保留最近：4 条
摘要长度：320 字
耗时：6.2 秒

    无需压缩

    当前历史消息较少，无需压缩。

    压缩失败

    记忆压缩失败，原会话保持不变。

    压缩过程应当先生成并校验新消息列表，成功后再替换原列表。模型调用失败时不能破坏现有会话。

    摘要要求

    压缩提示词至少约束以下内容：

    1. 只总结输入消息中明确出现的信息，不推测、不补充。
    2. 保留用户身份、偏好、目标、约束和明确决定。
    3. 保留姓名、时间、地点、数值、文件路径等精确信息。
    4. 区分用户说过的事实和助手给出的建议。
    5. 保留尚未解决的问题与当前任务进度。
    6. 删除寒暄、重复解释和已经失效的过程信息。
    7. 出现事实更新时，保留最新值，并说明旧值已经被替代。

    摘要示例：

    [历史摘要]
- 用户姓名：郝鑫磊。
- 用户正在本地学习 Qwen3-1.7B。
- 当前实验目标：实现终端 `/compact` 手动记忆压缩。
- 已决定：保留系统提示和最近 4 条原始消息。
- 待验证：压缩后能否正确召回旧事实。

    测试数据

    先构造一段固定的长对话，其中包含：

    • 用户姓名
    • 喜欢的运动
    • 当前居住地
    • 一个具体日期
    • 一个具体数字
    • 一项已经做出的技术决定
    • 一项尚未完成的任务
    • 若干无关寒暄和干扰信息

    所有实验组必须复用同一份对话，不能每组临时聊天。

    测试用例

    1. 早期事实召回

    在较早消息中写入：

    用户：我叫郝鑫磊。

    压缩后询问：

    用户：我叫什么？

    期望：回答“郝鑫磊”。

    2. 精确数字保留

    用户：这个实验最多循环 3 次。

    压缩后询问最大循环次数，期望回答“3 次”。

    3. 技术决定保留

    用户：记忆压缩先做手动命令，不做自动触发。

    压缩后询问当前决定，期望能区分手动命令与自动压缩。

    4. 最近上下文连贯

    在 /compact 前连续讨论一个问题，压缩后立即说：

    用户：继续刚才的第二步。

    期望：模型能根据保留的最近原文继续任务。

    5. 事实更新

    用户：我住在北京。
用户：我现在搬到杭州了。

    压缩后询问当前居住地，期望回答“杭州”，不能只保留旧值。

    6. 用户与助手归属

    用户：我喜欢羽毛球。
助手：我建议你也尝试游泳。

    压缩后询问用户喜欢什么，期望回答“羽毛球”，不能把助手建议误写成用户偏好。

    7. 短会话执行命令

    只有一两条消息时输入 /compact。

    期望：提示无需压缩，不调用摘要模型，也不改变消息列表。

    8. 连续执行命令

    连续输入两次 /compact。

    期望：第二次不重复压缩没有新增内容的历史。

    9. 压缩失败回滚

    模拟模型异常、摘要为空或格式不合法。

    期望：原消息列表保持完整，用户可以继续对话或再次执行命令。

    10. System Prompt 保持

    压缩前后检查第一条消息。

    期望：系统提示内容、角色和位置均不变化。

    记录指标

    指标 计算或判定方式
    消息压缩率 1 - 压缩后消息数 / 压缩前消息数
    字符压缩率 1 - 压缩后字符数 / 压缩前字符数
    Token 压缩率 1 - 压缩后 Token / 压缩前 Token
    事实保留率 正确召回的关键事实数 / 测试事实总数
    精确信息保留率 正确保留的姓名、数字、日期等 / 总数
    压缩延迟 输入 /compact 到消息列表替换完成的时间
    摘要幻觉数 摘要中原对话不存在的事实数量
    递归衰减率 第二次压缩后丢失的既有事实比例
    System 稳定性 系统提示是否保持原样

    当前项目已有字符统计，可以先记录字符压缩率；Token 统计作为后续补充，不能用字符数冒充 Token 数。

    主要失败模式

    摘要幻觉

    模型向摘要中加入原对话不存在的信息。需要强化“只提取、不推断”，并保留摘要全文用于检查。

    关键信息丢失

    姓名、数字、日期、文件路径或尚未完成事项被过度概括。需要在摘要提示词中明确列出必须保留的类型。

    事实归属错误

    把助手建议当成用户偏好，或把引用内容当成用户事实。摘要必须保留消息角色。

    新旧事实冲突

    摘要同时保留“北京”和“杭州”，却没有说明哪个是当前值。摘要规则应要求识别更新关系。

    System Prompt 污染

    系统提示被送入摘要、移动或覆盖。这项隔离必须由程序保证，不能依赖模型判断。

    递归压缩衰减

    多次总结同一份摘要导致细节逐步消失。实验中先测量问题，不提前加入复杂解决方案；确认现象后再比较“旧摘要直接合并”和“旧摘要参与重写”。

    压缩失败破坏会话

    先删除旧消息再请求摘要，一旦模型失败就无法恢复。正确顺序应该是先生成候选结果，校验成功后一次性替换。

    实现顺序

    1. 在终端入口识别 /compact，确认命令不会进入普通对话。
    2. 先实现 B 组规则裁剪，验证消息重组边界。
    3. 提取独立的记忆压缩函数。
    4. 编写专用摘要提示词，不复用 ReAct 提示词。
    5. 实现 C 组 LLM 摘要压缩和失败回滚。
    6. 输出压缩前后消息数、字符数和耗时。
    7. 固定测试对话，运行 A、B、C 三组。
    8. 增加第二次 /compact，运行 D 组递归衰减实验。
    9. 根据结果决定是否需要 Token 计数、摘要版本或增量压缩。

    实验边界

    本轮不处理：

    • 根据上下文阈值自动触发压缩
    • 让模型主动调用 memory_compact Tool
    • 跨会话记忆落盘
    • 向量检索和语义检索
    • LLM 自动提取长期用户事实
    • 多用户并发和会话隔离

    完成手动 /compact 实验后，再分别研究自动触发和模型自主 Tool Call。三者可以复用同一个压缩函数，但触发机制应保持独立。
